# __tmpl_title

An IRIS skill plugin: __tmpl_summary. Generated by
`iris plugin new __tmpl_name --kind skill`.

A skill is a **declarative** plugin (`flavor: declarative`): the manifest is the plugin.
There is no `setup()` to write -- IRIS reads each tool from the manifest, binds it to its
function, checks every call's arguments against the declaration before the function runs,
and runs the tool through the same governed loop as any other.

| File | What it is |
|---|---|
| `src/__tmpl_package/manifest.yaml` | the skill: each tool's `effect`, `description`, `impl` (the function) and `args` |
| `src/__tmpl_package/functions.py` | one plain function per tool |
| `tests/test_plugin.py` | the functions alone, then the skill in a real, governed IRIS (a good call and a refused one) |
| `tests/model_script.yaml` | what the scripted model answers |
| `tests/test_stable_tier.py` | the plugin imports only IRIS's stable tier |

## Try it

```bash
pip install -e ".[test]"
pytest
```

The tests need no model server and no network.

## Add a tool

1. The function in `functions.py`, taking the tool's arguments as keyword arguments and
   returning a string or something JSON can encode.
2. The tool under `tools:` in `manifest.yaml`: its `effect` (`read`, `write` or
   `destructive`), `description`, `impl: __tmpl_package.functions:<function>` and `args`
   (`string`, `number`, `integer`, `boolean` or `enum` with `options`; `required: false`
   and a `default` for an optional one).

IRIS refuses a manifest whose `impl` does not import or cannot take the declared `args`:
the plugin is not loaded, and the reason shows in `iris plugins` and System Health.

Import only the stable tier; `tests/test_stable_tier.py` holds you to it.
